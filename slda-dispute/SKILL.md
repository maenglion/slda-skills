# SLDA Dispute v4

상속: `slda-core`. verdict_mode = `determine`(문서상 책임귀속·증거관련성·이동 판정. 법적 책임·의도·인격 미판정).
**개인 총점 산출 금지.** 사람을 채점하지 않고 명제·증거·이동 단위를 채점한다(v3 → v4 핵심 수정).

## 1. 자료 신뢰도 표 (S0…Sn) — 분석 전 고정

S0 = 상대별 누적 원장(`slda-counterpart-ledger`)이 있으면 첫 행. confirmed_both 항목만 기준선, proposed는 참고.

| 열 | 내용 |
|---|---|
| ID | S1, S2… |
| 자료·시각 | 절대시각 미상이면 명기 |
| 역할 | 기준선 / 분쟁 사건 / 후속 협상 / 보조 기술로그 / 교정 대상 |
| 신뢰 메모 | 직접 전사(STT 오류 가능) / 메신저 원문 / 사용자 제공 로그(재실행 안 함) / 2차 분석물(1차 증거 아님) |

규칙: **기준선 자료와 분쟁 사건 자료를 혼동하지 않는다**(v3 결함: 37분 사전 통화를 분쟁 통화처럼 사용). 전사가 말줄임으로 끊기면 **보이지 않는 문장을 복원하지 않고**, 직후 양측의 재진술 문장으로 대체 판단하며 그 사실을 명기. 이전 버전 리포트는 교정 대상이지 판정 근거가 아니다.

## 2. 청구단위 원장 (claim-unit audit table)

모든 요약 수치는 이 표에서 계산한다. 열:

`ID · 쟁점군(issue_id) · 출처·위치(S#+타임코드) · 주체 · 정규화 명제(독립 검증 가능한 1명제) · 강도(0–4) · 증거자세 · 이동 · 확신(%)`

- 강도 0–4 = core §2 사다리(0 질문·인용 / 1 가능성 / 2 의심·추론 / 3 적극적 사실주장 / 4 범주적·가중).
- 증거자세: `none / circumstantial / documentary / testimonial / computed / contested`. 강도와 **독립** 코딩.
- 이동(drift) 기록 조건 4개 전부: 동일 쟁점군 · 비교 가능한 행위자·시점 · 실질적 의미변화 · 책임·증거·결론에 영향. 단순 보충설명 제외. 값: `none / attribution / evidence / issue / scope / contradiction / strategic_retreat`.
- 확신은 **숫자(%)**. "강/매우 강" 어휘 금지(v4 원본의 위반 사례 — 재발 금지).
- 제외 목록을 표로 남긴다: 사진 이미지·삭제 메시지·본안 소송문서(객체치환 여부만 사용)·욕설 빈도(독립 증거 아님)·개인 진단·성격·라이브 사이트 재검증.

## 3. 객체 계층 분리 (OBJECT)

한 단어가 여러 책임 객체를 덮으면 **먼저 분리**한다. 앵커: "DB" → ① 도메인·참조 DB(회사) ② 시연 운영 DB(외주 Mock) ③ 실제 운영 DB(회사 개발). 분리하면 "미완성"과 "동작함"이 동시에 참일 수 있음을 보인다. 분리 없이 귀속 채점 금지.

## 4. R&R 기준선

분쟁 **이전** 자료에서 반복 확인된 책임 구조를 표로: 영역 / 합의 내용 / 근거(타임코드) / 상대 수용 발언. 기준선 판정 문장 고정형: "X를 Y가 대신 완성하기로 한 합의는 확인되지 않는다. 오히려 반대 구조가 n회 반복 확인된다."
앞선 회의·통화 산출물(transcript §7 정합성 점검표)이 있으면 그 '합의' 행이 기준선의 1차 입력이다.
결정적 연결이 필요한 발언(예: "돈 더 주면 재구축")은 **직후 문맥 3개**로 목적을 고정한다.

## 5. 의도 vs 전달 — 합치지 말 것

핵심 분리: **"화자가 무엇을 뜻했는가(의도층)"** ≠ **"수신자에게 무엇이라고 전달됐는가(전달층)"**.
표: 논증 / 결론 / 근거 / 남는 문제. 판정 고정형: "자료는 의도를 설명하지만 그 의도가 수신자에게 전달될 문장으로 표현됐는가를 증명하지 않는다. 결론을 유지하면서 증명해야 할 명제가 바뀌었다." → attribution + evidence drift.

## 6. 증거 치환 (evidence substitution)

표: 결론 / 필수 전제 / 제시 증거 / 빠진 연결 / 판정(생존·부분 생존·강하게 생존·불생존).
규칙: **다른 채널·다른 수신자의 문장은 해당 채널 발언의 전달 증거가 아니다**(CHANNEL 필드). 부분 생존 시 "정확했을 응답"을 1문장으로 제시(관찰 보조, 훈수 아님).

## 7. 검증 비대칭 · 직접상충

- 검증 비대칭: 자기 자료는 증거로 채택하면서 공동 원문 검증은 거부 → 표(시각/요구/응답/판정).
- 객체치환: 분쟁 원문 분석 요청을 별도 문서 분석으로 전환.
- 직접상충: 동일 시점 부인→인정. **즉시 정정이면 장기 기망을 뜻하지 않는다고 명기**하되, 방어 중 사실확인 부정확의 증거로는 유지.

## 8. 상태 귀속 시간확장 (STATE)

초기 상태 언급은 **당시 근거 유무**와 **이후 반복의 시간범위**를 분리한다. 표: 시각/주체/발언/분석/영향. 규칙: 당사자가 현재 상태 회복을 명시한 시점 이후의 상태 단정은 `scope` 확장. 한쪽이 비판한 치환을 역으로 쓰면 그쪽도 `contradiction`으로 대칭 등재 — **후발 반격이 선행 문제를 소급해 지우지 않는다**. 정신질환·약 복용 여부로 주장 정확도를 대신 판단하지 않는다.

## 9. High-impact 매트릭스 + 적대검증

- F01…Fnn: 명칭 / 관찰 / 유형 / 영향(직접·강 / 직접 / 간접·강 / 간접) / 확신(%).
- **적대검증(adversarial check):** 핵심 판정마다 **가장 강한 선의적 대안**을 붙이고 재검토 결과(유지 / 부분 완화 / 철회)를 기록. 대안 적용 후 남는 **최소 결론** 1문장.

## 10. 최종 판정 + 컨텍스트 앵커

- 판정축 표(의도 / 전달 / R&R / 실제 산출물 / 각 당사자 대응)에 확신 %.
- "최종 한 문장" 1개. 미판정 선언(의도·인격·법적 책임).
- **Context anchor for another AI:** 고정 전제 번호 목록 + "분석 질문 고정(합치지 말 것)" + "평가 금지" 목록. 이 블록이 있어야 타 엔진 교차검증이 성립한다.
- 이전 버전 대비 수정 표(v3→v4): 항목 / 이전 / 현재 / 평가(중대 수정·보강·세분화·범위 확장).

## 11. 재검산 절차 (리포트 말미 고정)

(1) S1→Sn 순 화자·시각 정규화 (2) 독립 명제 분할 (3) 강도·증거자세 독립 코딩 (4) 동일 issue_id 앞뒤 비교 (5) 주요 판정 적대검증 (6) 표 행에서 화자·강도·drift 수 재계산.
