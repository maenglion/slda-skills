# SLDA 엔진 루브릭 · 동일지칭 기능·부호 분석 (R-10 v1.1)

**작성일:** 2026-09-09  
**적용 범위:** `litigation` · `contract` · `controversy` · `dispute`  
**연결 루브릭:** R-05 프로브 검출 · R-06 지칭 당위성 · R-11 종합 6축 채점 · R-13 게이트·논증 품질

## 1. 설계 목적

동일한 단어 또는 개념이 발화자·국면·문장 기능에 따라 서로 반대되는 역할을 하는지 판독한다.

> 같은 `AI`라는 개념이 한쪽에서는 검증과 이해를 위한 다리로 사용되고, 다른 쪽에서는 상대의 능력과 행위주체성을 제거하는 도구로 사용될 수 있다.

본 분석은 단순 긍·부정 감성분석이 아니다. 표면 단어가 아니라 다음을 함께 평가한다.

- 어떤 개념을 지칭했는가
- 누가 그 평가를 실제로 채택했는가
- 누구의 능력·책임·신뢰도에 영향을 주는가
- 어느 국면에서 어떤 목적으로 사용됐는가
- 현재 논점 또는 과거 사건과 어떻게 연결되는가
- 근거가 있는가
- 반론이 본안에 응답하는가

## 2. R-10 입력 필드

| 필드 | 정의 |
|---|---|
| `mention_id` | 개별 지칭단위 ID |
| `concept_id` | 표면 단어를 묶은 상위 개념. 예: `AI·Manus·Claude·AI 친구들` → `AI_TOOL_USE` |
| `surface_form` | 실제 문면에 등장한 표현 |
| `speaker` | 해당 문장을 말한 사람 |
| `stance_holder` | 그 평가를 실제로 채택한 사람. 인용·전언·반박과 자기주장을 분리하기 위한 필드 |
| `target_actor` | 지칭으로 능력·책임·신뢰도가 올라가거나 내려가는 대상 |
| `utterance_time` | 현재 발화 시각 |
| `reference_time` | 지칭 대상 사건의 시기: 현재·과거·미래·불특정 |
| `phase` | 작업지시·검증·협상·방어·공격·수리·종결 등 발화 국면 |
| `function_tag` | 검증·협업·설명·지시·거리두기·기각·폄하·화제전환 등 담화 기능 |
| `issue_relation` | 현재 논점과의 관계: 동일·인과 패턴·유사 사례·무관 |
| `evidence_posture` | 원문·문서·제3자·기억·추정·무근거 |
| `reference_confidence` | 생략된 지칭과 과거 사건까지 포함한 연결 확실성 1~5 |
| `response_class` | 직접답변·부분답변·구별제시·맞비난·인신공격·회피·침묵 |

### 핵심 필드: `stance_holder`

문장에 부정적 표현이 등장하더라도 그 표현을 발화자가 채택했다고 단정하면 안 된다.

- 상대 발언을 인용한 뒤 반박하는 경우: 부정적 표현의 `stance_holder`는 원발화자
- 제3자의 말을 소개만 하는 경우: 현재 화자의 채택 여부 별도 기록
- 조롱을 위해 상대 표현을 반복하는 경우: `mention_mode=parody` 등으로 분리

이를 구분하지 않으면 인용·반박문을 현재 화자의 태도로 잘못 합산하게 된다.

## 3. 기능 부호 5단계

| 점수 | 기능 | 판정 기준 | 예시 |
|---:|---|---|---|
| `+2` | 공동검증·이해의 다리 | 상대의 행위주체성을 보존하면서 공동 검증을 제안 | “네 Claude에도 전체 대화를 넣어 객관적으로 확인해봐.” |
| `+1` | 작업 촉진·보완 | AI를 보조도구로 사용하며 상대의 기여를 제거하지 않음 | “이 자료를 AI로 먼저 구조화해줘.” |
| `0` | 기술적 사실·중립 지칭 | 사용 사실이나 환경만 기술 | “이번 작업에는 Claude와 Manus를 사용했다.” |
| `-1` | 거리두기·기각 | AI를 이유로 상대의 근거나 설명을 약화 | “그건 네 AI가 한 말이잖아.” |
| `-2` | 능력 대체·폄하·자격 박탈 | 산출물과 의사결정을 도구에 전부 귀속해 인간의 기여를 제거 | “AI가 다 했는데 네가 한 게 뭐냐.” |

### 소유격 처리 원칙

`네/니 AI`라는 소유격 자체에는 부호를 부여하지 않는다. 소유격은 문맥 신호일 뿐 판정 기준이 아니다.

- “네 AI에도 검증시켜봐” → `+1~+2`
- “니 AI들이나 돌려봐” → 본안 거부·조롱·보조사 `이나`와 결합할 때 `-1~-2`
- “네 AI가 낸 견적도 비슷했다” → 상대 신뢰 채널을 근거로 호출하므로 `+1`

최종 부호는 **그 표현이 상대의 행위주체성을 보존하는지 또는 제거하는지**를 중심으로 판단한다.

## 4. 생략·과거 지칭의 확실성

기능 부호와 지칭 확실성은 서로 다른 축으로 유지한다.

| 등급 | 판정 | 가중치 |
|---:|---|---:|
| `5` | 동일 문장에 대상·행위·시기가 명시됨 | `1.0` |
| `4` | 앞뒤 발화에 명시된 단일 선행사를 지칭 | `0.8` |
| `3` | 대명사·생략이 있으나 대응 가능한 사건이 하나뿐임 | `0.6` |
| `2` | “늘 그랬다”와 같은 패턴 주장이고 사건원장에 대응 사건이 2건 이상 존재 | `0.4` |
| `1` | 과거 회상이지만 시기·사건·발화가 특정되지 않음 | `0.2` |
| `0` | 연결 근거 부족. 후보로만 보관하고 채점 제외 | `0` |

### 승급 규칙

추상적 패턴 주장이라도 사건원장의 독립된 기록과 연결되면 확실성을 승급할 수 있다.

예: “늘 내 커리어를 깎았다.”

- 단독 발화만 존재: `1`
- 서로 다른 시기의 대응 사건 2건 확인: `2`
- 각 사건의 문면·시각이 특정되고 현재 패턴과 연결: `3~4`

## 5. 과거 사건 소환과 주제 이동의 구별

오래된 관계나 반복 분쟁에서는 과거 사건 언급을 우선 `PATTERN 후보`로 분류한다. 오래됐다는 이유만으로 논점 이탈 처리하지 않는다.

| 현재 논점과의 관계 | 처리 |
|---|---|
| 현재 사건과 동일한 행위 | 감점 없음 · `SAME` |
| 동일한 인과·방어 메커니즘의 선례 | 감점 없음 · `PATTERN` |
| 단순 비교지만 공통점과 차이를 구체적으로 설명 | 약한 근거로 유지 · `ANALOGY` |
| 연결고리 없이 다른 잘못을 소환 | `SHIFT -1` |
| 본안에 답하지 않고 인신공격을 위해 과거만 소환 | `SHIFT -2` + 반론 응답성 감점 |

판정 기준은 과거 언급의 존재가 아니라 **현재 명제와 연결되는 브리지 문장이 제시됐는가**이다.

## 6. 반론 품질 5단계

| 점수 | 반론 형태 | 판정 기준 |
|---:|---|---|
| `4` | 근거 있는 직접 반박 | 동일 명제에 답하고 문서·사실·구별 기준을 제시 |
| `3` | 무근거 직접 반박 | 동일 명제에 답하지만 근거를 제시하지 않음 |
| `2` | 부분답변·구별제시 | 일부에 답하거나 범위·종류 차이를 구체적으로 설명 |
| `1` | 맞비난·양자화 | “너도 그랬다”처럼 자기 명제의 검증을 상대 문제로 치환 |
| `0` | 인신공격·화제전환·침묵 | 본안에 답하지 않음 |

### 독립 채점 원칙

욕설이나 공격적 어휘가 포함되더라도 본안에 대한 직접 반박과 근거가 존재하면 반론 품질은 별도로 인정한다. 공격적 표현은 R-11의 `존엄·강도 절제`에서 감점한다.

반대로 정중한 표현이라도 본안과 무관하면 반론 응답성은 낮게 판정한다.

## 7. 산식과 합산 원칙

기본 기능값은 다음과 같이 계산할 수 있다.

```text
weighted_function_score
= functional_polarity(-2~+2)
× reference_confidence_weight(0~1.0)
```

주제 이동과 반론 품질은 위 값에 즉시 합치지 않고 독립 필드로 유지한다.

```text
topic_shift_penalty = 0 / -1 / -2
rebuttal_quality = 0~4
```

이후 Total-King 단계에서만 목적에 맞게 종합한다. 조기 합산을 피해야 다음 경우가 구별된다.

- AI를 긍정적으로 언급했지만 현재 논점에서는 이탈한 경우
- AI를 부정적으로 언급했지만 본안 반박은 정확한 경우
- 공격적 어투이지만 근거 있는 반박을 제시한 경우
- 정중한 어투이지만 질문에는 답하지 않은 경우

## 8. 표준 출력 예시

```yaml
concept_id: AI_TOOL_USE

speaker_A:
  functional_polarity: +2
  function_tag: VERIFY_BRIDGE
  reference_confidence: 5
  issue_relation: SAME
  rebuttal_quality: 4

speaker_B:
  functional_polarity: -2
  function_tag: DEVALUE_DISQUALIFY
  reference_confidence: 5
  issue_relation: SHIFT
  rebuttal_quality: 1
```

리포트에는 다음을 표시한다.

1. 동일 개념의 화자별 기능 부호표
2. 기능 부호의 시계열 변곡
3. 서로 반대되는 기능으로 사용된 대표 문장쌍
4. 생략·과거 지칭의 확실성 및 연결 사건
5. 반론 응답성과 주제 이동 여부

## 9. 레지스트리용 5줄 정의

> **R-10 화자 조건부 동일지칭 기능·부호 분석**  
> **입력:** 개념 지칭단위, 화자, 평가대상, 국면, 지칭시기, 논점 연결, 근거 자세  
> **산식:** 기능부호 `-2~+2` × 지칭확실성 `0.2~1.0`; 주제이동은 별도 페널티  
> **평가시점:** 전문 시간순 정렬 및 사건원장 연결 이후  
> **구간화:** 강한 부정 / 부정 / 중립 / 긍정 / 강한 긍정  
> **표시:** 동일 개념의 화자별 부호표 + 시계열 변곡 + 반대 기능 문장쌍

## 10. 네 가지 모델 적용

| 모델 | 적용 예시 |
|---|---|
| `litigation` | 같은 `제공·위탁·보유`가 책임 인정인지 책임 회피인지 판독 |
| `contract` | 같은 `협의·완료·검수`가 의무인지 희망사항인지 판독 |
| `controversy` | 같은 `검증·사실`이 증거 요청인지 상대 봉쇄용 수사인지 판독 |
| `dispute` | 같은 `AI·외주·도움`이 협업인지 가치 절하인지 판독 |

R-10은 네 모델에 공통 적용되는 중앙 기능으로 두고, 결과를 다음 루브릭에 전달한다.

- R-05: 프로브 이후 회피·침묵 판정
- R-06: 과거 지칭의 당위성과 주제 이동 판정
- R-11: 반론 응답성·귀속 정확성·존엄 절제 합산
- R-13: 논점 게이트와 논증 품질 판정

## 11. 최종 정의

R-10은 키워드 감성분석이 아니라 **개념의 사용 목적을 화자축·시간축·국면축으로 계산하는 분석**이다. 같은 단어의 출현 빈도가 아니라, 그 개념이 상대의 능력·책임·신뢰도를 어떻게 변화시키는지를 측정한다.
