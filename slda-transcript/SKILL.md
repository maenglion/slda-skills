# SLDA Transcript v0.1

상속: `slda-core`. 산출은 **사실자료**(채점 대상 아님). 여기서 만든 파일이 dispute/controversy의 S1(기준선)·S3(사건) 자료가 된다.

핵심 원칙: **고치면서 지우지 않는다.** 모든 교정은 원문과 나란히 저장되고 규칙 ID가 붙는다. 교정 대조표가 없는 전사는 인용 근거로 쓰지 않는다.

## 1. 입력·오디오 검사

- 원음 파일 + STT 세그먼트(시작·끝·텍스트·화자 후보).
- 오디오 품질 1줄 기록: 평균 dBFS · 구간 편차 · 공백(무음) 구간 유무. 편차가 크거나 공백이 있으면 해당 구간 신뢰도를 낮춘다.
- 상대시각(+mm:ss)과 절대시각을 분리 기록. **절대시각 미확인이면 명기하고 메신저 시각과 직접 매칭하지 않는다.**

## 2. 화자 매핑 — 호칭 앵커

1. 화자 수 고정(2인 통화면 2로 고정).
2. **호칭 앵커**: "부사장님"을 부르는 발화 = 상대가 부사장 → 발화자는 그 반대편. 앵커로 재판정한 블록 수를 기록.
3. 한 세그먼트에 두 사람 말이 섞인 **혼입 블록**은 앵커로 못 잡는다(호칭이 한쪽만 나옴). 원음 재청취로만 분리 가능 → `MIXED` 태그.
4. 귀속 등급(블록마다):

| 등급 | 조건 | 인용 가능 |
|---|---|---|
| `A` | 호칭 앵커 또는 앞뒤 문맥으로 확정 | 개별 발언 귀속 인용 가능 |
| `B` | STT 화자 라벨만 | 인용 시 "화자 표기 기준" 병기 |
| `MIXED` | 혼입 의심 | **개별 귀속 인용 금지.** 구간 단위로만 언급 |

리포트 인용은 `A`만. `B`·`MIXED`를 근거로 쓴 판정은 `provisional`.

## 3. 용어집 교정 — 규칙 기반

- 전량을 읽고 **용어집(glossary)**을 만든다: `오전사 형태 → 정정 형태 · 규칙ID · 근거(도메인 용어/고유명사/반복 패턴)`. 예: "그 TV" → "DB", "크루드" → "CRUD", "갈아" → "가짜".
- 교정 범위 제한: **금액·수량·날짜·법령 조문 번호는 교정하지 않는다** (핵심 수치가 STT 오류인지 실발화인지 분석자가 결정하면 안 된다). 원문 유지 + `NUM?` 플래그.
- 오전사 의심이나 규칙 매칭 없음 → `STT?` 플래그 유지(v3 방식). 플래그 어절은 근거로 쓰지 않는다.
- 사적 대목·무관 구간은 삭제하지 않고 `EXCLUDED` 구간표(시작·끝·사유)로 뺀다.

## 4. 산출물

```
transcript_raw.csv        block_id · t_start · t_end · speaker_stt · text_raw
transcript_clean.csv      block_id · t_start · t_end · speaker · attribution_grade · text_clean · flags(STT?/NUM?/MIXED)
glossary.csv              rule_id · pattern_raw · replacement · scope · evidence · applied_count
correction_table.csv      block_id · text_raw · text_clean · rule_ids          ← 교정 대조표(부록 필수)
excluded_ranges.csv       t_start · t_end · reason
transcript_notice.md      전사 신뢰도 고지 (§5)
```

## 5. 전사 신뢰도 고지 — 리포트 상단 고정 블록

반드시 포함: 기계 전사 여부 / 적용한 교정 범위(화자 매핑·용어집만) / 전량 읽고 규칙 만들었는지 / 화자 확정 근거(N인 고정) / 혼입 블록 존재·건수 / 미교정 항목(금액·수량·날짜·조문) / 오디오 품질 1줄 / **"개별 발언을 특정인에게 귀속시켜 인용하지 마십시오 — 인용이 필요하면 원음 확인"** 경고 / 본문 인용은 등급 A만 사용했다는 선언.

## 6. 타임코드 앵커 인용 규칙

- 모든 인용에 `h:mm:ss` 또는 `+mm:ss` 부착. 앵커 없는 인용 금지.
- 인용은 `text_clean`이 아니라 **`text_raw`를 우선** 표시하고 교정본을 괄호로. 분석에서 교정본을 근거로 쓴 경우 rule_id 각주.
- 요약본과 전체본을 분리 배포할 때 요약본에 "전체본·교정 대조표는 별도" 링크 명기.

## 7. 연속 문서 정합성 (회의·통화가 시계열로 이어질 때)

통화가 앞선 회의·통화의 연장이면 리포트 말미에 **정합성 점검표**: `기존 결정(문서·일자) · 이번 대화 · 상태(유지/충돌/미다룸/전제 흔들림)`. 합의/액션(담당·기한·위치)/미결 3분류. 이 표가 dispute §4 R&R 기준선의 직접 입력이 된다.

## 8. 검증 체크리스트

- [ ] correction_table 행 수 == 교정 적용 블록 수
- [ ] 리포트 인용 전부 등급 A + 타임코드
- [ ] 금액·날짜·조문 교정 0건
- [ ] 혼입 블록 수·EXCLUDED 구간 고지에 명기
- [ ] 절대시각 미확인 시 메신저 매칭 안 함
