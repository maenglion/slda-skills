# SLDA 어투 드리프트(Stylistic Drift) 모듈 기획안 v0.1

**Semantic Logic Drift Analysis — Stylistic / Register Drift Engine**
제작: Soul Spectrum Inc.
성격: SLDA 본체 v0.1의 **확장 모듈**(신규 엔진 §6.5)
규율: 관찰 서술만 — 변화의 **양·분포·진폭은 산출**, **원인·진위·의도는 공백**

## 0. 이 문서의 위치 (정합성 노트)

- 본 모듈은 SLDA 본체 v0.1을 **대체하지 않고 확장**한다. 기존 4대 엔진(§6.1 Premise Extraction / §6.2 Premise Conflict / §6.3 Agent Attribution Shift / §6.4 Assertion Strength Drift)은 그대로 두고, **§6.5 Stylistic Drift**를 병렬 축으로 추가한다.
- 기존 엔진이 **"무엇을 말했나"**(내용·논점·주체귀속·표현강도)를 본다면, 이 모듈은 **"어떻게 말하나 / 그 방식이 언제 바뀌나"**(문장 구조·어투·정제도)를 본다.
- **명명 flag**: 본체 v0.1은 `Semantic Litigation Drift Analysis`로 표기되어 있으나, 제품이 계약서·연설·인터뷰·SNS 등 비(非)소송 텍스트로 확장되므로 본 기획안은 범용 표기 `Semantic Logic Drift Analysis`를 따른다. **약칭 SLDA는 유지.** 최종 확정은 결정 사항.
- **규율 flag**: v0.1 §8.1("결론 먼저 제시")·§8.5("법원 소결문 자동 생성")는 소송 도구 단계의 산출 방식이다. 본 모듈은 최신 규율 **"관찰까지, 결론 공백"**을 따르며, 원인·의도·진위를 산출하지 않는다. 본체 레거시 엔진을 동일 규율로 소급 조정할지는 별도 결정 사항으로 남긴다.

## 1. 모듈 정의

어투 드리프트 모듈은 한 화자(또는 한 주체가 낸 문서 묶음)의 **문체·어투·문장 구조가 시간·구간에 따라 어떻게 이동하는지**를 문장 단위 지표로 탐지·표시하는 엔진이다.

핵심 명제 한 줄:

> **어투가 바뀐 것은 데이터로 확정하되, 왜 바뀌었는지는 산출하지 않는다.**

한 변곡점에는 최소한 다음 원인들이 동시에 경합하며, 하나로 좁힐 수 없다: 진술 전략 변화 / AI 도구 도입·교체 / 대필·구술 / 대리인 수정 / 사안 자체의 성격 변화. 따라서 모듈은 **"바뀌었다"까지만** 산출하고, 원인 칸은 **공백**으로 둔다.

---

## 2. Governing 원칙 — 관찰 서술 규칙

모듈의 모든 산출물은 아래 경계를 넘지 않는다.

| 구분 | 산출한다 (O) | 산출하지 않는다 (X) |
|---|---|---|
| 변화 존재 | "X 지점에서 직접화법→완곡체로 이동" | "그러므로 회피/거짓" |
| 변화 양 | "문장당 claim 수 급증" | "몰아붙였다 = 조작" |
| 변화 분포 | "변곡점이 초반부에 집중" | "초반에 말을 맞췄다" |
| 변화 진폭 | "단정↔완곡 급전환 폭 큼" | "확신 없다 = 허위" |
| 정제도 | "구간별 편차 커 다회 수정으로 보임" | "여러 손 = 대필·공모" |
| 인칭 | "1인칭↔3인칭 법률체 전환 지점" | "인격이 바뀌었다" |

**원인·진위·의도 칸은 언제나 비운다.** 읽는 사람이 "왜 여기서 바뀌었지?"를 스스로 묻게 하는 것이 산출의 목적이며, 그 질문을 대신 답하지 않는다. (배열형)

## 3. §6.5 엔진 지표 정의

각 지표는 **기계적 집계**를 원칙으로 한다(사람의 주관 채점 최소화). 이는 §6.4 표현강도(0~100, 부분적으로 해석 채점 포함)보다 재현성이 높다.

### 6.5.1 Claim Density — 문장당 claim 수
- 정의: 한 종결(마침표) 안에 매달린 독립 사실·평가의 개수.
- 관찰: 한 문장에 사실이 다수 엉키는 "몰아붙임" 구간 탐지.
- 집계: 절 분리 후 술어핵 카운트. 기계적.
- 기존 엔진과의 구분: §6.1 Premise Extraction이 "전제 단위"를 뽑는다면, 6.5.1은 **한 문장에 몇 개가 압축되었는가**(밀도)만 센다.

### 6.5.2 Subject–Predicate Distance — 주어–술어 거리
- 정의: 주어부터 대응 술어까지의 어절 수(부사절·관형절 삽입으로 지연된 정도).
- 관찰: 술어가 길게 밀리는 회피·방어 리듬 vs 즉시 종결되는 직접 리듬.
- 집계: 의존구문 파싱 또는 규칙 기반 거리 측정. 기계적.

### 6.5.3 Nominalization Rate — 명사화율
- 정의: "~한 사정입니다 / ~로 볼 여지" 등 추상명사 종결·명사화 구문의 비율.
- 관찰: 구체 사실을 추상명사로 덮는 완곡·책임분산 신호.
- 집계: 명사화 패턴 사전 매칭 빈도 / 전체 종결 수. 기계적.

### 6.5.4 Assertion–Hedge Ratio — 단정↔완곡 비율
- 정의: 직접 종결("~입니다")과 완곡 종결("~로 볼 수 있습니다/보입니다")의 비율.
- 관찰: 이 비율이 **어느 구간에서 뒤집히는가** = 어투 변곡점의 핵심 신호.
- 집계: 종결어미 분류. 기계적.
- **기존 엔진과의 구분(중요)**: §6.4 표현강도는 개별 문장 내용주장의 **세기**를 0~100으로 본다. 6.5.4는 내용과 무관하게 **완곡/직접의 형식 비율과 그 이동**만 본다. 두 축이 **같은 지점에서 동시에 꺾이면** 오버레이로 표시(§4 참조)하되, 인과는 붙이지 않는다.

### 6.5.5 Subject-Mixing Index — 주체 혼입도
- 정의: 한 문장 안에서 교대하는 서로 다른 주체(인물·법인)의 수.
- 관찰: 한 문장에 여러 주체가 섞여 주어가 안 떨어지는 논지 흐림.
- 집계: 문장 내 개체(named entity) 주체 카운트. 기계적.
- 기존 엔진과의 구분: §6.3 Agent Attribution Shift가 "주체별 귀속 의미의 시계열 이동"을 본다면, 6.5.5는 **한 문장 안에서 주체가 몇 번 섞이는가**(문장 구조 층위)만 센다.

### 6.5.6 Person Shift — 인칭 이동
- 정의: 1인칭 서술("저는")과 3인칭 법률체("피고는")의 전환 지점·빈도.
- 관찰: 화자 시점이 오가는 구간(자필 서술↔대리 정제의 경계로 보이는 지점 등, 해석은 공백).
- 집계: 인칭 표지 분류. 기계적.

## 4. 산출물

### 4.1 어투 변곡점 타임라인
- 문서 묶음을 시간·구간순으로 놓고, 6.5.1~6.5.6 지표가 급변하는 지점을 표시.
- 각 변곡점에 **관찰 라벨만** 부착("직접→완곡 전환", "claim 밀도 급증"). 원인 라벨 없음.

### 4.2 표현강도(§6.4) × 어투(§6.5) 오버레이
- 세로 두 곡선: (a) 표현강도 곡선 = 내용 세기가 언제 올랐나, (b) 어투 변곡 곡선 = 문체가 언제 바뀌었나.
- **두 곡선이 같은 지점에서 꺾이는 겹침만 시각화.** "동시에 이동했다"는 사실이며, "그러므로 X"는 붙이지 않는다.

### 4.3 변화 분포·진폭·정제도 관찰
- 분포: 변곡점이 문서 초/중/후반 어디에 몰렸나("초반 집중" 등).
- 진폭: 전환의 크기(급전환 vs 미세 조정).
- 정제도: 구간별 명사화·정형표현 편차 → "다회 수정으로 **보인다**"까지(헤지 필수).

## 5. 금지선 (모듈 고유)

- 어투 변화로 **거짓말·조작·기망·의도**를 단정하지 않는다. → 심리감정·거짓말탐지 영역 침범이자 관찰 규율 위반.
- "완곡 증가 = 회피", "탈고 많음 = 은폐" 같은 인과 추론을 산출물에 박지 않는다.
- 안전선: "직접화법 비율이 X지점에서 Y% 하락" / "변곡점 초반 집중" / "다회 수정으로 보임"까지. **왜는 사용자 몫.**
- 이 사건(2024가합206528) 데이터로 데모 제작 시 **실명·식별정보 익명화.** 소송자료가 제품 마케팅에 실명 노출되지 않게 한다.

## 6. 재현성 (방어는 설계하지 않음)

- 6.5 지표는 대부분 기계적 카운트(claim 수·어절 거리·명사화 패턴·종결어미 분류)라, "그 집계가 틀렸다"는 반박 표면이 §6.4보다 작다.
- 재현 담보: 문장별 매칭 신호는 원자료(`style_units.csv`)에 기록. 동일 규칙 적용 시 동일 값 재현.
- **다만 방법론을 방어하는 설계는 하지 않는다.** 방법론 논쟁은 종결 불가능한 늪이며 논쟁 발생 자체가 격상이다. 재현성 각주는 "규칙 기반, 재현 가능" 최소 한 줄로 족하며 그 이상 확장하지 않는다. 실탄은 언제나 **대상 텍스트 원문**이지 모델이 아니다.

## 8. 출력 파일 (본체 명명 규칙 계승)

기존 v0.1 출력(`claim_units.csv`, `assertion_strength_report.md` 등)에 다음을 추가한다.

- `stylistic_drift_report.md` — 어투 변곡점 타임라인 + 분포·진폭·정제도 관찰.

**산출물에 `court_summary.md`(법원 소결문)에 대응하는 "결론 문단"은 만들지 않는다.** 어투 모듈은 관찰 리포트까지가 최종 산출이다. (§0 규율 flag 연동)
