## 운용
- 신규 루브릭은 5줄 정의 + 실데이터 검증 1회를 갖춰야 R-번호를 받는다. 검증 전에는 후보(RC-)로만 등재.
- 각 리포트 섹션 제목에 R-코드 병기 가능(예: "04. 검증 비대칭 [R-05·R-07·R-08]") — 엔진 간 검색 일관성 확보.
- MIRROR 반감 규칙(v1.1.4 — 인내 잔고, GPT 검토 5보완 반영): R-10 부호 전액 불변(계측층). 필드 분리 — raw_polarity / confidence_weight / weighted_harm / balance_delta(적립은 +표기) / balance_after. MIRROR 성립 5요건: 동일 concept_id + 동일 evaluation_dimension + 동일 function_family + 행위자·대상 역전 + 열린 issue_thread. 잔고 수명 = issue_thread 개방~폐쇄(폐쇄 이벤트: 사과 수리·정정 완료·합의 종결·관계 종료·원용 중지 합의) — phase와 분리, 이월 금지·기록 보존. 계산 기준 = sequence_index(병합 실순서), 보고서 재배치 시 명시. 반사 = min(반사량, available_balance)까지 ×0.5, excess_amount 전액. ⑥축 환산(잠정 구간표, 캘리브레이션 대상): 반감 적용 절대치 0→10 / ≤3→8 / ≤8→6 / ≤15→4 / ≤25→3 / >25→2. 3열 병기(원값/제외값[비교용, 최종 사용 금지]/반감 적용값[최종]). 양측 대칭.
- R-10 반례 체크 규칙(v1.1.1): 인스턴스 부호가 화자의 원장 사전확률과 2점 이상 상충하면 PRIOR_CONFLICT 플래그 → 2차 검사(① stance_holder 재확인 ② mention_mode=MIRROR 판별: 동일 concept 반대 부호 선행 + 대상 역전 + 동일 국면 ③ 프레임 일관성). 부호는 유지(타격 계측), 주석으로 구별(프레임·반사 여부) — 부호에 세계관 평가를 섞지 않는다. MIRROR는 Total-King 합산에서 별도 행 표시, 양측 대칭 적용 필수.
- R-10 v1.1(GPT 설계안 통합)은 4모델 공용 허브 — 산출(issue_relation·확실성·반론품질)을 R-05·R-06·R-11·R-13에 전달. issue_relation 어휘 단일화: SAME/PATTERN/ANALOGY/SHIFT(−1/−2) — 구 R-06 목적태그(APT/PAT/ATK/SHIFT)는 각각 SAME/PATTERN/(신설)/SHIFT−2·−1로 사상. 'contract' 모델 참조는 장래 모듈로 각주 처리.
