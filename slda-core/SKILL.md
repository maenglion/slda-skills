# SLDA Core · 공통 규약 v1.0

제작: Soul Spectrum Inc. · 설계: 맹난영
성격: 모듈 공통 상위 규약. 모듈별 SKILL.md는 이 문서를 **상속**하며 충돌 시 이 문서가 우선한다.

## 0. 모듈 라우팅 (입력 유형 → 모듈)

| 입력 | 모듈 | 산출 성격 |
|---|---|---|
| 유사 선례 검색·1회성/다회성 판정·패턴 확정 | `slda-case-index` (전·후 공통) | 태그 택소노미·cases.jsonl·선례 참조 블록 |
| 같은 상대와 반복되는 분쟁의 사전 맥락 | `slda-counterpart-ledger` (기준선 S0) | 관계 계약·합의·금지선·미결·회복 신호 누적 |
| 통화·회의 녹음 STT 결과 | `slda-transcript` (전처리) | 교정 대조표·신뢰도 고지·귀속 등급 A/B/MIXED |
| 소송 서면·신청서 묶음(시간순) | `slda-litigation` | 프레임·표현강도·귀속 시계열 + 전제충돌 |
| SNS·커뮤니티 다자 논쟁(게시글·댓글·인용문서) | `slda-controversy` | 게이트 채점·E1–E6·후퇴 벡터·전제충돌 |
| 문서제출명령·금융/과세정보·사실조회 신청서 묶음 | `slda-inquiry` | 결합 단위·침해 강도축 0–5·D-01~05·법적 등급표 |
| 1:1 계약·외주·정산 분쟁(통화 전사+메신저) | `slda-dispute` | 청구단위 원장·책임귀속·증거치환·적대검증 |
| 논쟁 안의 AI·권위 원용 행위 | `slda-ai-invocation` (오버레이) | 원용 신호 7종·INVOKE_MODE |
| 한 화자의 문체·어투 변화 | `slda-stylistic-drift` (오버레이) | 기계적 지표 6종·변곡점 |
| 산출물을 HTML/PDF 리포트로 | `slda-report-html` | 고정 CSS 스캐폴드 렌더 |

오버레이 모듈은 본체 모듈 위에 얹는다. 단독 실행 가능하나 원자료(`utterance_units`)는 본체 규격을 따른다.

## 1. 절대 금지 (전 모듈 공통)

1. 논쟁·소송 **대상 사안의 사실적 진위**를 판단하지 않는다. (부정선거 여부, 위법 여부, 손해 존부, 조작 여부)
2. 화자의 **동기·의도·기망·정신상태**를 추정하지 않는다. 텍스트에 있는 것만 쓴다.
3. **시계열을 재배열하지 않는다.** 원문 순서가 곧 근거다. 순서 오류는 분석 무효.
4. "~로 보인다", "~인 듯하다" 금지. 5단계 척도 또는 %로 표기한다.
5. 인용은 원문 워딩 그대로. 요약·의역을 인용부호 안에 넣지 않는다.
6. 검증되지 않은 것을 확정으로 올리지 않는다. (§6 상태표 규칙)
7. **상대 반박을 근거로 충돌을 만들지 않는다.** 전제충돌은 본인 텍스트 양쪽에서만 성립한다.
8. 후발 행위로 선행 문제를 소급해 지우지 않는다. 각 이동은 그 시점에 고정된다.
9. 욕설·비꼼 **빈도·강도**를 독립 점수 지표로 쓰지 않는다. (SARC_ROLE 규칙만 적용)
10. 인용된 문서와 그 인용자는 **별개 주체**다. 문서의 한계기재·검증조건을 인용자 점수로 계상하지 않는다.

## 2. 척도 — 한 사다리, 두 해상도

주장/표현의 세기는 **5단계 사다리 하나**로 통일한다. 0–4 정수 또는 0–100 연속값 중 모듈이 선택하되, 라벨은 아래로 고정한다.

| 0–4 | 0–100 | 라벨 | 정의 |
|---|---|---|---|
| 0 | 0–20 | 사실·인용 | 인용·질문·확인된 사실 기재 |
| 1 | 21–40 | 가능성 | "~일 수 있다" 류 |
| 2 | 41–60 | 추정·의심 | "~로 추정된다", 의심 제기 |
| 3 | 61–80 | 강한 평가 | 적극적 사실주장, 평가 술어 |
| 4 | 81–100 | 확신·단정 | 범주적 단정, 법적·형사 프레임 술어 |

**논증 품질 점수**(controversy E1–E6 등)와 **침해 강도축**(inquiry 0–5, 요구범위의 침해성)은 별개 척도다: 0–20 붕괴 / 21–40 취약 / 41–60 부분 / 61–80 견고 / 81–100 강함. 두 척도를 한 표에 섞지 않는다.

**확신도 표기**는 반드시 숫자다: `확신 0.85` 또는 `85%`. "강/중/매우 강" 같은 어휘 표기는 금지(v4 ADOMS 보고서 위반 사례). 필요하면 5단계 라벨을 병기한다.

## 3. 선처리 필드 — 채점 전에 모든 발화 단위에 부착

이 단계를 건너뛴 채점은 무효다. 오분류의 대부분이 선처리 누락에서 발생했다.

| 필드 | 값 | 규칙 |
|---|---|---|
| `REFERENT` | 지시 대상 식별자 | 욕설·자질어·법령 언급 등 **표면 형식으로 먼저 분류하지 말고** 지시 대상을 먼저 확정. 미해소 발화는 목록화 후 질의 |
| `FRAME_OWNERSHIP` | `self` / `adopted` | 선행 마커("그럴거면", "~님 식 계산으로 치자면", "~대로 하면", "~라면 ~겠네", "그 전제로 가면") → `adopted`. 직후 문장이 그 식을 기각하면 확정. adopted 수치는 화자 주장이 아님(귀류 RDX) |
| `SARC_ROLE` | `replace` / `garnish` | replace = 논증 자리를 비꼼·동기·자질이 대체 → 감점 대상. garnish = 논증 후 덧붙음 → 감점 금지 |
| `SARC_MODE` | `declare` / `fatigue` / `overpolite` / `numeric` | 기록만. 점수 미반영 |
| `INVOKE_MODE` | `explore` / `assert` | AI·외부자료 원용 시. explore=탐색 중(불리 판정 수용 여부가 지표), assert=확정 산출물 보유(산출물–주장 정합이 지표). 두 모드는 같은 저울에 올리지 않는다 |
| `STAGE_LEVEL` / `STAGE_ATTRIB` | 1–4 | 1 anomaly / 2 outlier / 3 irregularity / 4 fraud evidence. LEVEL(화자가 주장한 단계) ≠ ATTRIB(상대가 읽은 단계)이면 "단계 혼동" 등재 |
| `OBJECT` | 대상 객체 식별자 | 한 단어("DB", "보고서", "분석")가 여러 객체를 덮으면 계층 분리. 분리 없이 채점 금지 |
| `CHANNEL` | 통화 / 메신저 / 게시글 / 서면 / 이메일 / 캡처재인용 | 다른 채널·다른 수신자의 문장은 해당 채널 발언의 전달 증거가 아니다 |
| `REPLY_TO` | 응답 대상 turn_id | 응답 관계가 끊기면 논점 이탈로 보이는 오분류 발생 |
| `ATTRIBUTION_GRADE` | `A` / `B` / `MIXED` | 통화 자료 전용(transcript §2). A만 개별 귀속 인용 가능 |
| `SPEAKER` / `AUTHOR` | 발화자 / 저자 | AI 붙여넣기·캡처 재인용 시 분리. 미분리 시 LAUNDER·INVOKE 상호 오염 |

## 4. 원자료 — 재현성의 근거

- 모든 요약 수치는 **원자료 행에서 계산**한다. 암산·추정 금지. 산식은 코드로 검산하고 각주에 남긴다.
- 원자료 파일: `utterance_units.csv`(발화 단위) → `claim_units_scored.csv`(채점 단위). 리포트 헤더 카운트 == 행 수 검사 필수.
- 채점 루브릭은 영업비밀. 공개 리포트에는 **무엇을 세었는가(빈도·문장·출처)는 전부 공개**, **어떻게 채점했는가(규칙)는 비공개**하되 원자료 SHA-256을 리포트에 고정한다. 요청 시 동일 해시 파일 제출.
- 방법론 방어는 설계하지 않는다. "규칙 기반, 재현 가능" 한 줄로 족하다. 실탄은 대상 텍스트 원문이지 모델이 아니다.

## 5. 이동(drift) 공통 어휘

모듈마다 이동 태그가 다르므로 상위 어휘로 매핑한다. 리포트에는 모듈 태그를 쓰되 원자료 `drift_class` 컬럼에는 상위 어휘를 기록한다.

| 상위 | litigation | controversy | dispute(v4) | 정의 |
|---|---|---|---|---|
| `ISSUE` | 프레임 대체 | RET(논점 이동) | issue | 쟁점을 다른 쟁점으로 교체 |
| `PREMISE` | 전제충돌 PC | RET(전제 부인) | — | 전제 자체를 바꾸거나 부인 |
| `EVIDENCE` | 제3자 조회 확장 | RET(근거 격하) | evidence | 근거를 다른 근거·채널로 치환 |
| `ATTRIBUTION` | 주체귀속 이동 | — | attribution | 책임·행위 주체를 바꿈 |
| `SCOPE` | — | RET(변수 배제) | scope | 시간·범위·객체 범위를 확장·축소 |
| `STRENGTH` | 표현강도 변곡 | — | — | 같은 명제의 세기만 이동 |
| `CONTRADICTION` | PC | PC | contradiction | 동일 시점 직접상충 |
| `RETREAT_CONCLUSION` | — | FIX | strategic_retreat | 결론이 후퇴(가점 방향) |
| `ADVANCE` | 근거 추가 | ADV | — | 근거 추가·강화 |
| `REDUCTIO` | — | RDX | — | 상대 식 조건부 채택 후 기각. 이동 아님 |

**후퇴 벡터 원칙:** 후퇴 자체는 감점이 아니다. **결론**이 후퇴하면 신뢰도 상승, **근거**가 후퇴하면(결론 고정·받침대 교체) 신뢰도 하락. 세야 할 것은 후퇴 건수가 아니라 후퇴 벡터다.

## 6. 산출 규율 — verdict_mode

모듈 실행 전에 하나를 고정한다. 리포트 표지에 명기한다.

| 모드 | 산출 범위 | 사용처 |
|---|---|---|
| `observe` | 변화의 존재·양·분포·진폭까지. 원인·의도·진위 공백 | stylistic-drift, ai-invocation, 제품 데모 |
| `rank` | 논증 품질 채점·순위. 사안 판정 없음 | controversy |
| `determine` | 문서상 책임귀속·증거관련성까지 판정. 법적 책임·의도 미판정 | litigation(당사자 제공용), dispute |

**상태표(4단계)** — 모든 리포트 말미에 둔다. 확정 칸에 올릴 수 있는 것은 2종뿐: **관측 사실**(공표·원문) / **검산 결과**(독립 재계산). 그 외는 가능성 / 검증 필요 / 판단 안 함. 게이트 채점 결과를 사안 판정으로 승격하지 않는다. 토이모델 산출은 "가능성"이다.

**오버클레임 격하:** "형사 확정", "징계 확정", "패소", "조작" 등 근거 없는 단정은 `provisional`로 격하하고 %를 붙인다.

## 7. 정합성 유지 — 복수 산출물

- 같은 사건에 복수 리포트(소외인편·피고편 등)가 존재하면 **합본 금지**. 합본은 상대의 공모·실질동일 프레이밍을 강화한다.
- 3계층 일관성: L1(절대 동일 필수: 날짜·수치·인용) / L2(전략적 차별화: 독립성 증명) / L3(의견 차이 허용).
- 조문·판례·안건번호·수치는 원문 대조 후 사용. 불일치 발견 시 지적(예: 17-0581 → 17-0506 정정 사례).

**패턴 문장 규칙:** "늘·매번·원래" 류 빈도 서술은 `slda-case-index`에서 선례 ≥2건이 검색될 때만 허용. 없으면 "이번에".

## 8. 반복 실행 구조

선처리 → 채점 → 검토 → 정정 루프를 **명시적으로 여러 회** 반복한다. 오분류 패턴이 수렴할 때까지. 각 회차에서 발견한 엔진 결함은 형식을 고정해 기록한다:

```
결함 #n · [무엇을] [어떻게 잘못 읽었나] · [원문에 마커가 있었는가] · [어느 선처리 필드로 방지할 것인가]
```

앵커값(캘리브레이션 사례)과 불일치하면 그 섹션만 재실행한다. **앵커에 맞추려고 점수를 조정하지 않는다** — 선처리 필드 누락부터 본다.

## 9. 다른 엔진에 넘길 때 — 컨텍스트 앵커

단기기억 모델·타 엔진에 넘길 때는 리포트 앞에 **고정 전제 블록**을 둔다: 진영/역할 맵, 객체 계층 분리, 채널별 증거 구분, 분석 질문 고정(합치지 말 것 목록), 평가 금지 목록. 이 블록 없이 넘긴 결과는 교차검증 대상이 아니다.

**코퍼스 창 정렬:** 두 산출물(자기 엔진 vs 타 엔진, run n vs run n+1)의 자료 구간이 다르면 점수 비교 금지. 교집합 구간만 feature 단위로 대조하고, 한쪽에만 있는 구간은 "창 밖"으로 표기한다. 채점 축이 다르면(논증 채점 vs 관계 귀책) 같은 발화에 반대 부호가 붙을 수 있다 — 오분류가 아니라 가정 차이이므로 양쪽 가정을 먼저 적는다.

## 10. 알려진 미확정 (결정 사항 · total_king 이관)

1. 개인 종합점수 존치 여부 — controversy는 논증 총점 산출, dispute v4는 개인 총점 폐기. 현재 규칙: **rank 모드에서만 논증 총점 허용, determine 모드에서는 명제·증거·이동 단위만**.
2. E1–E6 가중치·게이트 상한값.
3. `stance`(ai-invocation) ↔ `INVOKE_MODE`(core) 통합 — 현재 규칙: INVOKE_MODE가 상위, stance는 하위태그.
4. 명명 `Semantic Litigation` → `Semantic Logic` 통일 (약칭 SLDA 유지).
5. litigation 레거시 §8.1 "결론 먼저"·§8.5 "소결문 자동생성"을 observe 규율로 소급할지.
